# Mini NPU Simulator

Python 3.8 이상에서 실행하는 콘솔 프로그램입니다. 외부 패키지 없이 Python 표준 라이브러리(`json`, `time`, `math`, `re`, `pathlib`)만 사용합니다.

## 1. 파일 구성

```text
Mini_NPU_Simulator/
├── main.py       # 프로그램 본체
├── data.json     # 미션에서 제공한 테스트 데이터
└── README.md     # 실행 및 구현 설명
```

`main.py`와 `data.json`은 반드시 같은 폴더에 둡니다.

## 2. 실행 방법

1. Python 3.8 이상을 설치합니다.
2. 위 세 파일을 같은 폴더에 둡니다.
3. 터미널(명령 프롬프트)에서 해당 폴더로 이동합니다.
4. 다음 명령을 실행합니다.

```bash
python main.py
```

- `1` 선택: 3×3 필터 A, B와 입력 패턴을 직접 입력합니다. 각 행에는 숫자 3개를 공백으로 구분해 입력합니다.
- `2` 선택: `data.json`의 필터와 패턴을 읽어 일괄 판정합니다.

## 3. 구현 요약

### MAC 연산

`mac(pattern, filter_matrix)` 함수가 핵심 계산을 담당합니다. 두 배열의 같은 행·열 위치에 있는 값을 곱하고, 그 결과를 `total` 변수에 계속 더합니다. 이 계산이 Multiply-Accumulate, 즉 MAC입니다.

예를 들어 입력과 필터가 모두 아래와 같다면 점수는 5입니다.

```text
0 1 0       0 1 0
1 1 1   ×   1 1 1
0 1 0       0 1 0
```

계산식은 `0×0 + 1×1 + ... + 0×0 = 5`입니다. NumPy 등 외부 수치 계산 라이브러리는 사용하지 않고 중첩 `for` 반복문으로 직접 구현했습니다.

### 라벨 정규화

`normalize_label()`은 입력 표현을 프로그램 내부의 두 표준 이름으로 통일합니다.

- `+`, `cross`, `Cross` → `Cross`
- `x`, `X` → `X`

이렇게 해야 JSON의 표기가 서로 달라도 같은 의미로 비교할 수 있습니다.

### JSON 구조 해석

- `filters` 안의 `size_5`, `size_13`, `size_25`는 크기별 기준 필터 묶음입니다.
- 각 필터 묶음의 `cross`, `x` 키는 각각 Cross와 X 필터를 뜻합니다.
- `patterns` 안의 `size_13_2` 같은 키에서 `13`을 추출해 `size_13` 필터를 선택합니다.
- 각 패턴의 `input`은 실제 입력 배열이고 `expected`는 기대 정답 라벨입니다.

### 입력 검증과 예외 처리

`validate_matrix()`는 배열이 비어 있지 않은지, 행과 열의 수가 같은지, 모든 값이 유한한 숫자인지 검사합니다. JSON 모드에서 특정 케이스가 잘못되었으면 해당 케이스만 FAIL로 기록하고 다음 케이스를 계속 처리합니다. 사용자 입력 모드에서는 형식이 잘못되면 다시 입력하도록 안내합니다.

### 동점 처리와 epsilon

`decide()`는 두 점수의 차이의 절댓값을 확인합니다. 차이가 `1e-9`보다 작으면 `UNDECIDED`로 판정합니다.

컴퓨터의 실수(float)는 일부 소수를 정확히 표현하지 못할 수 있습니다. 따라서 단순히 두 값이 완전히 같은지 비교하지 않고 작은 차이를 허용하는 epsilon 정책을 사용합니다. 이 프로그램은 미션 권장식인 `abs(score_cross - score_x) < 1e-9`를 적용합니다.

### 성능 측정

`measure_mac()`은 MAC 함수만 10회 실행하고 평균 시간을 밀리초(ms)로 환산합니다. 파일 읽기나 화면 출력 시간은 측정 구간에 포함하지 않습니다. 연산 횟수는 N×N 배열에서 각 위치를 한 번씩 계산하므로 `N²`입니다.

## 4. 실제 제공 data.json 실행 결과

제공된 JSON을 직접 실행한 결과는 다음과 같습니다.

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| size_5_1 | 0.9 | 0.9 | UNDECIDED | X | FAIL |
| size_5_2 | 8.9 | 0.1 | Cross | Cross | PASS |
| size_13_1 | 0.3 | 14.7 | X | X | PASS |
| size_13_2 | 7.5 | 7.5 | UNDECIDED | Cross | FAIL |
| size_25_1 | 4.9 | 4.9 | UNDECIDED | X | FAIL |
| size_25_2 | 52.9 | 0.1 | Cross | Cross | PASS |

- 전체 테스트: 6개
- 통과: 3개
- 실패: 3개

### FAIL 원인 분석

1. 미션 설명의 예시에는 총 8개 테스트가 표시되어 있지만, 실제 제공된 `data.json`의 `patterns`에는 6개 케이스가 있습니다. 프로그램은 파일에 실제 존재하는 6개를 기준으로 집계합니다.
2. `size_5_1`은 Cross와 X 점수가 모두 0.9입니다. 두 점수 차이가 epsilon보다 작으므로 결과는 `UNDECIDED`입니다. 하지만 데이터의 expected는 `x`(정규화 후 X)이므로 FAIL입니다.
3. `size_13_2`는 두 점수가 모두 7.5입니다. 결과는 `UNDECIDED`이고 expected는 `+`(정규화 후 Cross)이므로 FAIL입니다.
4. `size_25_1`은 두 점수가 모두 4.9입니다. 결과는 `UNDECIDED`이고 expected는 `x`(정규화 후 X)이므로 FAIL입니다.
5. 위 세 건은 배열 크기 오류나 JSON 파싱 오류가 아닙니다. MAC 계산 결과가 동점이어서 발생한 판정 정책과 expected 사이의 불일치입니다.
6. 동점일 때 임의로 Cross 또는 X를 선택하면 미션에서 요구한 `UNDECIDED` 규칙을 위반하게 됩니다. 따라서 코드는 동점 규칙을 유지하고 FAIL 사유를 보고합니다.
7. `+`와 `x`를 각각 Cross와 X로 통일했기 때문에 라벨 표기 차이 자체가 원인이 되는 오류는 방지했습니다.
8. 따라서 현재 데이터의 FAIL 3개를 PASS로 바꾸기 위해 판정 로직을 임의로 변경하는 것은 권장하지 않습니다. 데이터 작성자가 의도한 정답이나 동점 정책을 확인해야 합니다.

## 5. 성능 분석 및 시간 복잡도

실행 환경에서 한 번 측정한 예시입니다. 실행 환경, CPU 부하, Python 버전에 따라 시간은 달라질 수 있으므로 고정된 성능 보장값이 아닙니다.

| 배열 크기 | 연산 횟수 N² | 평균 시간 예시(ms) |
|---|---:|---:|
| 3×3 | 9 | 0.003292 |
| 5×5 | 25 | 0.006790 |
| 13×13 | 169 | 0.044826 |
| 25×25 | 625 | 0.134587 |

2차원 배열의 행을 한 번 순회하는 반복문과 각 행의 열을 순회하는 반복문이 중첩되어 있습니다. 크기가 N인 정사각형 배열은 총 N×N개 위치를 방문합니다. 따라서 곱셈과 누적 덧셈 횟수는 N²에 비례하며 시간 복잡도는 O(N²)입니다.

예를 들어 한 변의 길이가 2배가 되면 전체 위치 수는 4배가 됩니다. 실제 실행 시간은 반복문 실행 비용과 시스템 상태 등의 영향을 받으므로 정확히 4배가 되지는 않을 수 있습니다. 특히 작은 배열에서는 함수 호출 및 시간 측정 자체의 오버헤드가 측정값에 상대적으로 크게 반영될 수 있습니다.

## 6. 주요 함수 빠르게 찾아보기

| 함수 | 역할 |
|---|---|
| `normalize_label()` | 라벨 표준화 |
| `validate_matrix()` | 배열 구조와 숫자 검증 |
| `mac()` | 핵심 MAC 계산 |
| `decide()` | Cross / X / UNDECIDED 판정 |
| `measure_mac()` | MAC 평균 실행 시간 측정 |

| `run_json_mode()` | JSON 케이스 일괄 판정 및 결과 보고 |
| `main()` | 프로그램 시작 및 메뉴 선택 |
